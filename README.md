# zoo3323.github.io

NamJuKim의 1인 개발자 개발 기록입니다. <https://zoo3323.github.io>

`main`에 올린 파일을 GitHub Pages가 그대로 내보냅니다. HTML은 `tool/build.py`가 앱 정보 파일에서 만들어 내고, 만든 결과를 함께 올립니다.

## 구성

| 경로 | 내용 |
|---|---|
| `tool/site.json` | 개발자 이름, 이름 아래 소개 한 줄, 주소, 앱 페이지를 만들 앱(이 순서가 「다른 작업」·「만든 것」의 순서) |
| `tool/shelf.json` | 첫 화면 맨 위의 스티커 묶음(만든 사람)과 진열대의 줄(회사 프로젝트, 개인 프로젝트의 앱·도구, 연구·논문과 대회·창업 — 이 순서), 줄마다 거는 물건 |
| `tool/apps/<앱>/app.json` | 앱 한 개의 정보(이름, 색, 버전, 플랫폼, 설명) |
| `tool/apps/<앱>/pack.html` | 진열대의 봉지 속에 넣을 물건 |
| `tool/apps/<앱>/preview.html` | 앱 페이지의 「미리보기」 |
| `tool/apps/<앱>/demo.html` | (있으면) 미리보기 아래의 따로 해 보는 구역. 구역을 더 두려면 `app.json` 의 `"demos": [{"file", "title", "id"}]`(demo.html 앞에 나온다) |
| `tool/about.json` | 소개 페이지 `/about/`의 내용(경력·학력·자격증·회사 프로젝트·개인 프로젝트·연구·논문·기술·공개한 도구) |
| `tool/build.py` | 위 파일들로 HTML을 만든다. `site.css`·스크립트 주소 끝에 내용 해시(`?v=`)를 붙여, 새로 올리면 브라우저가 옛 사본(GitHub Pages 10분 캐시) 대신 새 파일을 받는다 |
| `index.html`, `<앱>/index.html`, `work/<이름>/index.html`, `about/index.html`, `404.html` | 만들어진 결과. 직접 고치지 않는다 |
| `assets/site.css` | 화면 전체의 모양 |
| `assets/wall.js`, `light.js` | 봉지와 벽에 붙인 사진·포스트잇의 흔들림, 빛(PC는 마우스를 따르는 등빛과 봉지의 반사·무지개 결, 안드로이드 폰은 기울기를 따르는 봉지의 반사) |
| `assets/aisle.js` | 첫 화면 진열대 줄을 미는 화살표 단추, 줄 아래 위치 막대(손가락으로 미는 폰에서 「옆에 더 있다」를 알려 줌), 처음 온 사람에게 넘치는 줄이 한 번 살짝 밀렸다 돌아오는 힌트(브라우저마다 한 번, `localStorage` 의 `zoo3323:peek`, 움직임 줄이기면 안 함) |
| `tool/resume.mjs` | `resume/index.html`(빌드가 만드는 A4 이력서)을 `assets/resume.pdf` 로 굽는다(Playwright 필요) |
| `tool/video/` | 회사 프로젝트의 설명 영상. `scenes/<slug>.js`(장면)를 `render.mjs` 가 프레임마다 찍어 `assets/video/<slug>.mp4`·표지 `.webp` 로 굽고, 장마다 시작 시각을 `clips.json` 에 적는다 |
| `assets/clip.js` | 설명 영상: 보일 때만 소리 없이 되풀이, 지금 장의 줄 밝히기, 줄을 누르면 그 장으로, 멈춤 단추 |
| `assets/shots.js` | 미리보기 화면을 눌러 크게 보기 |
| `assets/grab.js` | 넘치는 진열대 줄·앱 화면 줄을 마우스로 잡아 옆으로 끌기(편 손·쥔 손 커서, 놓으면 가까운 멈춤 자리로) |
| `assets/cursor/` | 사이트 커서 그림 다섯(레몬 화살표 `arrow`, 가리키는 손 `point`, 편 손 `open`, 쥔 분홍 손 `fist`, 돋보기 `zoom`; 32px·64px). 원본은 `tool/cursor/*.svg`, 고친 뒤 `node tool/cursor/render.mjs` 로 다시 굽는다(Playwright 필요). 쓰는 곳은 `site.css` 맨 위의 `--cur…` 변수. 같은 이름으로 다시 구우면 브라우저 캐시에 옛 그림이 남을 수 있으니 이름을 바꾼다 |
| `assets/pet.js`, `closet.js` | 스크린펫 꺼내 보기, 옷 분류 딱지 |
| `assets/tryon.js` | 옷장 「배경 지우고 AI로 입혀 보기」 시연(옷 고르기 → 배경 지우기 → 내 사진 고르기 → 입혀 보기, 결과 비교 막대). 웹에서 AI 를 돌리지 않고 미리 만든 그림만 보여 준다 |
| `assets/img/`, `assets/fonts/` | 그림과 글꼴 |

첫 화면은 마트 진열대처럼 칸으로 나뉜 벽에 고리로 건 봉지들이고, 봉지를 누르면 나오는 앱 페이지는 앱 장터의 앱 화면처럼 짜여 있습니다.

## 고친 뒤 만들기

```sh
python3 tool/build.py          # HTML 다시 만들기 (파이썬 기본 기능만 씁니다)
python3 -m http.server 8765    # http://127.0.0.1:8765 에서 미리 보기
```

주소가 `/assets/…`처럼 맨 위부터 시작하므로 파일을 직접 열지 말고 서버로 띄워서 봅니다.

## 앱을 더할 때

1. `tool/apps/_template` 폴더를 새 이름으로 복사합니다. 폴더 이름이 곧 주소입니다(`tool/apps/weather` → `/weather/`).
2. `app.json`을 채웁니다.
   - `tone`, `ink`: 봉지의 색과 그 위에 올리는 글자색. `accent`: 흰 바탕에서 쓰는 강조색.
   - `pack`: `card`(한 장짜리 색 판) 또는 `bag`(헤더 카드를 박은 봉지, 봉지 색은 `bag`).
   - `platforms`: `[{"name": "Android", "requires": "8.0 이상"}, {"name": "iOS", "requires": "17 이상"}]`처럼 적습니다. 안드로이드 앱의 페이지에는 Google Play 배지가 늘 나오고, 주소가 없으면 배지 옆에 `status`가 적힙니다. 플레이에 내지 않는 앱(시험용 APK 등)은 `"play": false`를 적으면 배지 대신 `status`만 나옵니다. `store`에 스토어 주소를 넣으면 배지가 그 주소로 이어집니다(배지 그림은 구글이 배포하는 공식 그림 `assets/img/google-play-badge.png`, 페이지 맨 아래에 구글이 요청하는 상표 문구가 함께 나옵니다).
   - `status`: 봉지의 둥근 딱지와 스토어 주소가 없을 때의 버튼에 적히는 말.
   - `mark`: 이름 글씨. 비워 두면 팻말 글씨로 적고 크기는 카드 폭에 맞춥니다.
3. 그림을 `assets/img/<앱>/`에 넣습니다. `icon.webp`(256px 정사각형)는 꼭 있어야 합니다.
4. `pack.html`, `preview.html`의 그림 주소를 고칩니다. 봉지 속에는 `window`(화면 한 장의 윗부분)나 `showcase`(세로로 긴 그림 하나)를, 미리보기의 PC 화면에는 `shots shots--wide`를 씁니다.
   - 웹 서비스처럼 패키지 이름이 없으면 `package` 대신 `code`에 바코드로 찍을 짧은 이름을 적습니다.
5. `tool/site.json`의 `apps`에 폴더 이름을 넣고, `tool/shelf.json`에서 걸 칸의 `items`에 `"app:<폴더 이름>"`을 넣은 뒤 `python3 tool/build.py`를 돌립니다. 앱 페이지의 「다른 작업」도 함께 바뀝니다.

### 진열대(`tool/shelf.json`)

- `profile`은 맨 위 벽에 붙인 스티커 묶음입니다.
  - 폴라로이드 사진: `photo`에 그림 주소를 넣으면 그 사진이, 비워 두면 `monogram` 글자가 나옵니다. 지금 사진은 `assets/img/profile.webp`(증명사진 그대로 413×531, 메타데이터 없음)입니다. 사진 칸은 증명사진 비율(3.5×4.5)의 세로 칸이고, 다른 비율의 사진은 칸에 맞춰 가장자리가 잘립니다. 아래 여백 글씨는 `caption`입니다. 크기는 `assets/site.css`의 `--pw`(구멍 간격의 몇 배)이고, 테두리·글자·테이프가 따라 큽니다.
  - 사진과 포스트잇은 봉지처럼 움직입니다. 화면을 굴리면 붙인 윗변을 축으로 봉지의 반만큼 흔들리고, PC에서 마우스를 대면 손이 가까운 쪽이 벽에서 살짝 들립니다. 이름표는 통째로 붙인 스티커라 움직이지 않습니다.
  - 이름표: `label`, `role`, `org`, `line`. 누르면 `href`(소개 페이지)로 갑니다.
  - `stickers`:
    - `kind: note`는 포스트잇입니다. `title`(학력·경력)과 `rows`(줄마다 `logo`, `name`, `detail`, `when`)를 적습니다.
    - `kind: seal`은 자격증 딱지(정보처리기사)입니다. 소개 묶음 맨 끝, 마지막 포스트잇 오른쪽 아래에 작게 붙습니다.
    - 색은 `tone`, 기울기는 `tilt`입니다.
  - 학교·기관 마크는 `assets/img/marks/`에 있습니다(경북대·대구대 공식 UI 묶음, 한국산업인력공단 공식 로고 SVG). 경북대 UI 관리지침은 상업적 사용을 금지하고 외부인 사용에 허가를 요구합니다.
- `rows`는 그 아래 줄입니다. 줄마다 고리 한 줄이고, 옆으로 밀어 봅니다.
  - 한 갈래만 거는 줄은 `name`(벽에 박은 띠의 이름)과 `items`(물건, 왼쪽부터)를 적습니다(회사 프로젝트).
  - 한 줄을 칸 여럿으로 나눌 때는 `items` 대신 `bays`에 칸마다 `id`, `name`, `items`를 적습니다. 칸마다 띠가 따로 박히고, 띠도 물건과 함께 밀립니다.
    - 줄에 `name`이 있으면 한 갈래를 나눈 것입니다. 띠마다 줄 이름을 작게 앞에 붙입니다(개인 프로젝트 › 앱, 개인 프로젝트 › 도구).
    - 줄에 `name`이 없으면 갈래 둘이 한 줄을 나눠 쓰는 것이라 띠가 곧 칸 이름입니다(연구·논문, 대회·창업). 세로로 덜 길어지게 한 줄에 두었습니다.
    - 다 들어가는 줄은 띠가 벽 양 끝까지 닿게 칸을 늘리고 물건을 칸 가운데로 모읍니다. 띠 폭과 들임은 `build.py`의 `place_bays`가 정합니다.
  - `pop`을 적으면 판촉 스티커가 붙습니다(예: 모두의 창업). 나눈 칸에 적으면 그 칸 띠의 오른쪽 끝에 붙어 함께 밀리고, 폰에서는 띠 안에 길쭉하게 붙습니다.
- 물건은 두 가지입니다. `"app:pocketpet"`은 그 앱의 봉지이고, 객체는 작은 봉지입니다.
- 작은 봉지에는 다음을 적습니다.
  - `name`, `kind`(어디 것인지), `line`(한 줄), `tone`·`ink`(색), `href`(누르면 갈 곳)
  - 그림: `image`(실제 화면 그림 주소, 가로세로 약 1.9:1) 또는 `art`(`build.py`의 `ART`에 그린 도식 이름)
  - 넓게 걸 때는 `wide`
- 줄 밀기와 크기
  - 마우스가 있는 화면에서는 넘치는 줄 양 끝에 화살표 단추가 나옵니다(`assets/aisle.js`).
  - 넘치는 줄은 마우스로 잡아 옆으로 끌 수도 있습니다(`assets/grab.js`, 앱 화면 줄 `.shots`도 같음). 커서는 레몬색 편 손, 끄는 동안은 분홍색 쥔 손입니다(그림을 못 쓰는 브라우저는 기본 손). 끄는 동안 scroll-snap 을 끄고, 던지면 관성으로 미끄러집니다: 놓은 빠르기 그대로 출발해 지수로 느려지고(시간 상수 `GLIDE`), 그 빠르기로 갈 거리 근처의 물건 시작(고리가 구멍에 꽂히는 자리)에 정확히 선 뒤 scroll-snap 을 되살립니다. 줄이 움직이는 동안(끄는 중·미끄러지는 중)은 줄 안의 카드가 누르기를 받지 않아(`.is-moving`), 던지고 손을 떼거나 미끄러지는 줄을 눌러 세워도 카드가 열리지 않습니다. 끌지 않고 가만히 누르면 원래대로 열립니다. 손가락 화면은 건드리지 않습니다.
  - 크기는 `build.py`의 `SIZE`입니다. 진열대의 물건은 모두 같은 비(넓은 화면 0.7, 폰 1.2)로 걸어서 봉지와 카드의 글씨 크기가 같습니다. 기준은 회사 프로젝트의 그림 카드(넓은 화면 9칸, 폰 16칸)이고, 앱 봉지는 같은 비로 7칸(폰 12칸)입니다. 넓은 화면의 폭은 홀수라 물건은 반 칸에서 시작합니다. 물건 사이는 2칸입니다.
- 고리는 봉지 크기와 상관없이 벽의 크기입니다.
  - 물건은 줄 왼쪽에서 정수 칸만큼 떨어져 놓이고, 밀다가 물건의 시작에서 멈춥니다(scroll-snap). 그래서 멈추면 고리의 두 다리가 늘 구멍에 꽂힙니다.
  - 스티커 묶음의 높이도 구멍 간격의 정수배라서, 그 아래 칸의 고리가 구멍 자리에 섭니다.
  - 스티커 묶음 안의 크기는 벽 칸에 묶음 비(`.maker`의 `--mk`)를 곱해 진열대 카드에 맞춥니다. 넓은 화면·태블릿·폰은 1.2배, 936~1199px는 한 줄에 들어가는 1.15배입니다. 묶음 높이는 화면 폭마다 스티커가 들어가는 가장 낮은 칸 수(넓은 화면 9칸, 태블릿 15칸, 폰 18~27칸)이고, 320~735px를 잘게 나눠 재서 정했습니다.
  - 폰에서 줄 맨 끝 칸은 오른쪽에 2칸을 둡니다(`MODES["narrow"]["end"]`). 봉지 오른쪽 위의 둥근 딱지가 봉지 밖으로 나와 있어, 한 칸이면 끝까지 밀었을 때 고리가 구멍에서 비킵니다.

### 회사 프로젝트 자세히 보기(`/work/<이름>/`)

- 내용은 `tool/about.json`의 `work`에 있습니다. 줄마다 `slug`(주소), `org`(이름), `unit`(회사), `period`, `role`, `summary`, `notes`, `did`(맡은 일), `stack`(쓴 기술)을 적습니다.
  - `flows`(「구성」 구성도): `[{"title", "note", "steps": [노드 | {"group", "nodes": [노드...]}]}]`, 노드는 `{"name", "note", "kind": in|step|model|out}`. 넓은 화면은 왼쪽→오른쪽, 860px 이하는 위→아래로 흐르고, 모델·AI 단계는 레몬, 결과는 연보라, 함께 쓰는 것은 점선 묶음입니다.
  - `problems`(「풀어야 했던 문제」): `[{"problem", "solution"}]`. 수치 없이, 무엇이 막혔고 어떻게 풀었는지만 한 줄씩 짧게(스무 자 안팎) 적습니다. 줄글로 길게 쓰지 않습니다.
  - 설명 영상: `tool/video/scenes/<slug>.js` 가 있으면 「풀어야 했던 문제」에 영상이 붙고, `problems` 줄 하나가 영상의 장 하나입니다(자막도 그 글을 씁니다). 장면은 사이트 그림체의 도식(SVG)이고 실제 화면·현장 영상이 아닙니다.
    - 굽기: `node tool/video/render.mjs [slug ...]`(Playwright·ffmpeg(libx264)·cwebp 필요). 1280×720·30fps H.264, 끝은 바탕색으로 잠깐 비웠다가 처음으로 돌아가 되풀이가 이어집니다. 정지 화면만 보려면 `--stills 0,2.5 --out 폴더`.
    - `problems` 글이나 장면을 고치면 다시 굽고 `python3 tool/build.py` 를 돌립니다. 장 시작 시각은 `tool/video/clips.json` 에서 빌드가 읽습니다.
    - 장면 파일은 `tool/video/stage.html`(브라우저로 `?scene=<slug>` 를 붙여 열면 그대로 재생), 공용 그리기는 `lib.js`, 주차장(2.5D·라벨링)은 `lot.js` 입니다.
    - 쪽에서는 화면에 보일 때만 재생하고, 움직임 줄이기 설정이면 저절로 틀지 않습니다. 영상 주소에도 내용 해시(?v=)를 붙입니다.
  - 페이지 순서: 설명 → 구성 → 풀어야 했던 문제 → 맡은 일 → 쓴 기술 → 자료.
- 진열대의 회사 프로젝트 봉지와 소개 페이지의 「자세히 보기」가 이 페이지로 이어집니다. 색과 도식은 진열대 봉지(`tool/shelf.json`)의 `tone`·`ink`·`art`를 따릅니다.
  - 봉지에 `image`(그림 주소)와 `imageSize`(가로·세로)를 적으면 도식 대신 그 그림이 봉지와 이 페이지 머리, 「다른 작업」 작은 그림에 나옵니다.
  - `"photo": true`를 함께 적으면 그림 카드가 됩니다. 넓은 화면 9칸·폰 16칸으로 넓고, 그림을 카드 폭에 가깝게 그림의 비율대로 둡니다(`imageSize`의 가로/세로). 크기와 높이는 `build.py`의 `SIZE["photo"]`와 `PHOTO`이고, CSS(`.pack--photo`)가 같은 값으로 그립니다. 그림 아래 글은 글씨의 px 하한까지 셈해, 칸이 가장 작은 폭(넓은 화면 936px, 폰 320px)에서도 「보기」와 겹치지 않게 높이를 잡습니다.
  - 지금은 회사 프로젝트 다섯과 논문 카드에 미니어처 디오라마 풍으로 만든 그림(`assets/img/work/<이름>/card.webp`, `assets/img/research/card.webp`, 900×600, 3:2)을, 도구 네 개는 원래의 화면 그림(가로로 긴 비율)을 그림 카드에 넣습니다.
- 이미지·영상은 `work[].media`에 `{"type": "image" 또는 "video", "src", "w", "h", "alt"}`로 적습니다(영상은 `poster`도). 적은 것이 있을 때만 「자료」 구역이 생깁니다. 파일은 `assets/img/work/<이름>/`에 둡니다.
  - `caption`은 그림 아래 짧은 설명입니다. 실제 자료가 없어 만든 그림은 `"generated": true`로 적으면 설명 옆에 「생성 이미지」 딱지가 붙습니다(그림 귀퉁이에도 「생성 이미지 · 예시」를 그려 둡니다).
  - 「자료」 줄의 그림은 비율이 달라도 높이가 같고, 폭은 그림 비율대로입니다.
- 회사 자료는 공개해도 되는 것만 싣습니다(현장·고객이 드러나면 가립니다).
- 글은 AI·컴퓨터 분야에서 흔히 쓰는 용어(amodal 검출, 지식 증류, RAG, 호모그래피 등)로, 짧고 구체적인 문장으로 씁니다. 처리 시간·정확도 같은 수치와 고객·현장 이름, 사내 모델·저장소 이름은 적지 않습니다(2026-10-19 사용자 결정).
  - 지금 라벨링 도구·2.5D 차량 하단면 검출 그림은 사내 라벨링 도구의 CCTV 화면(카메라 보정, 보정값으로 바닥에 올린 격자, 주차면 찬 칸·빈 칸)이고, 번호판·사람·간판을 흐리게 했습니다. 도구는 읽기만 하고(GET) 아무것도 저장하지 않았습니다.
  - 안전 영상 분석·위험성평가 AI 그림은 실제 자료가 없어 만든 그림이고, 감지 상자는 직접 그렸습니다.

### 개인 프로젝트

- 소개 페이지의 「개인 프로젝트」 구역(`#h-projects`)은 `tool/about.json`의 `projects`입니다. 지금은 스코어랩(모두의 창업 2기), 가나디야(모두의 창업 1기), Claude Code 에이전트 플러그인 셋이고, 회사 프로젝트 바로 다음에 나옵니다. 예전의 「대회·창업」·「LLM·에이전트」 구역은 여기와 겹쳐 없앴습니다(진열대의 모두의 창업 스티커도 이리로 옵니다).
- 줄마다 `org`(이름), `unit`(무엇 · 모두의 창업 같은 이력), `period`, `notes`(LLM·에이전트를 어떻게 붙였는지를 한두 문장, 수치 없이), `link`·`linkLabel`(또는 링크 여럿 `links: [{href, label}]`), 그리고 줄 앞 그림 `art`를 적습니다.
- 줄 아래에는 그 줄들에 나오지 않은 앱(`site.json` 의 `apps`)과 공개 도구(`about.json` 의 `tools`)만 「그 밖의 앱」·「그 밖의 도구」 작은 목록으로 붙습니다. 예전의 「만든 것」·「공개한 도구」 구역은 겹쳐서 없앴습니다.
  - `art` = `{"images": [...], "size": [가로, 세로], "fit": "cover"|"phones"|"stack", "tone": 바탕색}`. `cover` 는 한 장을 칸(3:2)에 채우고, `phones` 는 폰 화면 여러 장을 아래에서 올라오게, `stack` 은 넓은 그림 두 장을 겹쳐 둡니다.
  - 회사 프로젝트·논문 줄의 그림은 따로 적지 않아도 진열대 카드 그림(`shelf.json` 의 `image`)을 씁니다.
  - 폰에서는 그림 옆에 이름·소속·기간만 두고 설명은 아래 온 폭으로 내립니다.
- 예전 과제인 감정 기반 음료 추천과 한국어 일상대화 챗봇은 싣지 않고, 코딩 에이전트로 앱을 만든다는 문구도 쓰지 않습니다(2026-10-19 사용자).
- 가운뎃점으로 이은 말(「폭·기울기」)은 한눈에 보기·맡은 일·소개 목록에서 줄 끝에서 끊기지 않게 묶습니다(`build.py`의 `keep_dots`).

앱에 딸린 문서는 그 앱의 경로 아래에 둡니다(예: `pocketpet/privacy.html` 파일 → `https://zoo3323.github.io/pocketpet/privacy`).

### 개인정보처리방침

- 본문은 `tool/apps/<앱>/privacy.html`에 쓰고, `app.json`에 `"privacy": {"date": "시행일"}`을 넣습니다. 그러면 `<앱>/privacy.html`이 만들어지고 앱 페이지 「정보」 맨 끝에 「개인정보처리방침」 줄이 생깁니다.
- 모든 방침 끝에 붙는 문의처·구제 기관·변경 안내는 `tool/privacy-common.html` 한 곳에 있습니다. 본문의 `{{email}}`, `{{developer}}`, `{{date}}`, `{{app}}`은 만들 때 채워집니다. 문의 메일은 `tool/site.json`의 `email`이고, 사이트에서는 방침 페이지에만 보입니다.
- 공개한 방침 주소는 앱 안과 플레이 콘솔에 걸립니다. `tool/site.json`의 `keep`에 적어 두면, 그 페이지를 만들지 못할 때 `build.py`가 멈춥니다. 주소(앱 폴더 이름)는 바꾸지 않습니다.
- 방침 페이지는 플레이 스토어와 앱에서 누구나 들어오는 곳이라 포트폴리오로 가는 길을 두지 않습니다. 위의 팻말(이름 링크·뒤로 단추)과 발치의 GitHub 링크가 없고, 링크 미리보기에도 첫 화면 그림(`og.png`)을 쓰지 않습니다. 남는 링크는 문의 메일과 구제 기관 같은 바깥 주소뿐입니다. 앱 페이지에서 방침으로 가는 링크는 그대로입니다.
- 내용을 바꾸면 `date`를 새 시행일로 고칩니다.

## 그 밖에 고칠 때

- **개발자 이름, 소개 한 줄**: `tool/site.json`의 `developer`, `tagline`을 고치고 다시 만듭니다. 링크 미리보기 그림 `assets/img/og.png`는 첫 화면을 1200×630으로 다시 찍어 바꿉니다.
- **버전 기록**: 그 앱의 `app.json`에서 `version`을 올리고 `history` 맨 위에 `{"version", "date", "notes"}`를 하나 더합니다. 앱 페이지의 「새로운 기능」에는 지금 버전의 기록이, 그 아래 접힌 「버전 기록」에는 나머지가 나옵니다. 버전이 없는 웹 서비스는 `version`을 `null`로 두면 「업데이트 기록」이 됩니다.
- **소개**: `tool/about.json`의 경력·학력·기술·공개한 도구를 고칩니다. 소개 페이지에서 `career`는 「경력」, `education`은 「학력」 구역으로 따로 나옵니다. 앱 페이지의 개발자 이름은 소개 페이지로 이어집니다. 「다루는 기술」은 줄 세 개(비전 AI·LLM·개발) 안팎으로 짧게 둡니다. `"main": true`인 줄은 노란 칩으로 진하게 보입니다.
- **이름 글씨를 따로 쓰는 앱**: 이름 글자만 담은 글꼴 조각을 `tool/wordmarks.py`로 만들고 `assets/site.css` 맨 위에 `@font-face`를 한 줄 더한 뒤 `app.json`의 `mark.font`에 그 이름을 적습니다.
- **옷장 체험 칸 그림**(`assets/img/mylittlecloset/try/`): 인물 2·옷 3은 Codex 이미지 생성(가상 인물·생성 이미지), 옷 배경은 맥 Apple Vision(`VNGenerateForegroundInstanceMaskRequest`)으로 지움, 입힌 결과 `result-<인물>-<옷>.webp` 6장은 FASHN tryon-v1.6(앱과 같은 설정: 흰 바탕 옷 JPEG, flat-lay, balanced). 인물·옷을 늘리면 결과도 조합마다 새로 만들어야 합니다(유료). 그림마다 만든 방법은 `*.webp.json`(저장소 밖)에 적어 둡니다.
- **스크린펫 동물 추가**: `assets/img/pocketpet/`의 `thumb/`, `atlas/`(스프라이트 위 다섯 줄, 1536×1040), 큐티 그림체면 `stage/`에 그림을 넣고 `tool/apps/pocketpet/demo.html`의 선반에 버튼 한 줄을 더합니다.
